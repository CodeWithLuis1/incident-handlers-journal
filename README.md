## 🗂️ Entry #1 — Ransomware attack on a healthcare clinic

| Field | Detail |
|---|---|
| **Date** | _9/19/2026_ |
| **Entry #** | 1 |

### 📝 Description

A small U.S. healthcare clinic specializing in primary care services experienced a **ransomware attack**. On a Tuesday morning, around 9:00 a.m., several employees were unable to access their computers or critical files such as patient medical records. A **ransom note** appeared on their screens stating that the files had been encrypted and demanding a large sum of money in exchange for the decryption key. The incident brought the organization's operations to a complete halt and forced a shutdown of its computer systems.

### 🛠️ Tools used

No specific investigation tools were documented for this incident, as it corresponds to an initial analysis exercise of the event.

Tools that would be **relevant** in a real investigation of this type:

- **SIEM** (Security Information and Event Management) — to correlate logs and detect anomalous activity.
- **EDR / antivirus** — to identify and contain the malware on endpoints.
- **Email security / anti-phishing tools** — to trace the entry vector.
- **Network analysis tools** (e.g., packet capture) — to review suspicious communications.

### 🔎 The 5 W's of the incident

| | Question | Answer |
|---|---|---|
| **Who** | Who caused the incident? | An organized group of unethical hackers, known for targeting organizations in the **healthcare and transportation** sectors. |
| **What** | What happened? | The attackers sent **targeted phishing emails** with a malicious attachment. Once downloaded, it installed malware that gave them access to the network. They then deployed **ransomware**, which encrypted critical files. A ransom note demanded money in exchange for the decryption key. |
| **When** | When did it occur? | On a **Tuesday morning, at approximately 9:00 a.m.** |
| **Where** | Where did it happen? | On the healthcare clinic's **network and computers**: employee workstations and the systems storing patient medical records. |
| **Why** | Why did it happen? | **Financial** motivation: to extort the company for a ransom. The attackers exploited the **human factor** through phishing to gain initial access. |

### 🗒️ Additional notes

- **Entry vector:** targeted phishing email with a malicious attachment → highlights the need for **security awareness training** for employees.
- **Impact:** complete disruption of operations and loss of access to sensitive patient data (possible regulatory implications, e.g., **HIPAA** in the U.S.).
- **Initial response:** the company shut down its systems and contacted external organizations to report the incident and receive technical assistance.
- **Open question:** were there isolated (offline) backups that would allow data restoration without paying the ransom?
- **Takeaway:** this case shows how a single phishing email can escalate to a full organizational shutdown, and the importance of layered defenses (backups, network segmentation, EDR, training).

## 🗂️ Entry #2 — Malware Analysis & Incident Response (Trojan / Malicious Executable)

| Field | Detail |
|---|---|
| **Date** | *09/27/2026* |
| **Entry #** | 2 |

### 📝 Description

An alert generated by the SIEM was detected following the unauthorized execution of an executable file on a corporate endpoint. The incident originated via a social engineering vector (phishing), where a user downloaded and executed a file camouflaged as a legitimate Windows utility (`bfsvc.exe`), triggering the execution of a malicious payload on the device.

### 🛠️ Tools used & Technical Artifacts

* **Analysis Tools:** VirusTotal, SIEM correlation engines, static and dynamic artifact analysis.
* **Key Indicators of Compromise (IoCs):**
  * **File Name:** `bfsvc.exe`
  * **File Size:** 430.00 KB (440,320 bytes)
  * **SHA-256 Hash:** `54e6ea47eb04634d3e87fd7787e2136ccfbcc80ade34f246a12cf93bab527f6b`
  * **MD5 Hash:** `287d612e29b71c90aa54947313810a25`
  * **SHA-1 Hash:** `8f35a9e70dbec8f1904991773f394cd4f9a07f5e`

* **Threat Intelligence Results (VirusTotal):**
  * **Detection Verdict:** **52 / 71** security vendors flagged the file as malicious.
  * **Popular Threat Label:** `Trojan.flagpro/fragtor` (Primary classification as a Trojan).
  * **Sandbox Behavior:** Execution in isolated environments (such as CAPE Sandbox and Yomi Hunter) showed evasion techniques, runtime module deployment (`runtime-modules`), debugging detection routines (`detect-debug-environment`), and callbacks to external Command and Control (C2) network resources.

* **Tools relevant for real investigations:**
  * **SIEM** — for log correlation and anomaly detection across the network.
  * **EDR / Antivirus** — for containment and rapid isolation of the compromised endpoint.
  * **Email Security / Anti-phishing** — for tracing the initial entry vector.
  * **Network Analysis (PCAP)** — for auditing connections to external URLs and suspicious domains.

---

### 🔎 The 5 W's of the incident

| | Question | Answer |
|---|---|---|
| **Who** | Who caused the incident? | A Trojan executable file (`bfsvc.exe`) operating under the `Trojan.flagpro/fragtor` malware family. |
| **What** | What happened? | A malicious file disguised as a legitimate binary was executed on an organizational asset. Upon running, it interacted with multiple external network resources and exhibited backdoor and Trojan capabilities, triggering a massive alert across 52 out of 71 antivirus engines. |
| **When** | When did it occur? | Captured in system telemetry and analyzed on the current date (September 27, 2026). |
| **Where** | Where did it happen? | Across organizational endpoints and reflected in institutional SIEM logs. |
| **Why** | Why did it happen? | Exploitation of the human factor via social engineering to achieve initial arbitrary code execution and compromise the security posture of the asset. |

---

### 🗒️ Additional notes

- **Static & Dynamic Forensics:** The utilization of cryptographic hashes (SHA-256) enabled the unambiguous identification of the sample within global threat databases, confirming it is not a false positive due to the high detection ratio (52/71).
- **Mitigation & Containment:** It is imperative to immediately isolate the affected device from the network, revoke active credentials on the host, and proceed with a deep remediation or re-imaging of the operating system.
- **Lessons Learned:** Reinforce perimeter and email security controls, alongside the implementation of strict application whitelisting policies to prevent unauthorized binaries from running on user workstations.
